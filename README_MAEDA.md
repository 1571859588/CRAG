# CRAG Baseline on MAEDA Benchmark

This directory extends the original CRAG (Corrective RAG) implementation to support the **MAEDA benchmark** (OpenROAD EDA domain QA).

## What is CRAG?

CRAG (Corrective Retrieval-Augmented Generation) improves RAG by assessing the quality of retrieved documents before generation:

1. **Retrieve** passages for the query (BGE + FAISS)
2. **Evaluate** retrieval quality with a cross-encoder evaluator (correct / ambiguous / incorrect)
3. **Refine** knowledge based on evaluation:
   - **Correct**: Extract relevant strips from retrieved docs (internal refinement)
   - **Ambiguous**: Combine internal + external knowledge
   - **Incorrect**: Use external knowledge (BGE top passages, replacing original web search)
4. **Generate** answer using the refined knowledge (Qwen1.5-14B-Chat)

## MAEDA Integration

### Key Differences from Original CRAG

| Component | Original CRAG | MAEDA CRAG |
|-----------|--------------|------------|
| Retriever | Contriever / BM25 | Fine-tuned BGE-large-en-v1.5 + FAISS |
| External knowledge | Web search (Google) | BGE top passages (no web search for OpenROAD domain) |
| Generator | Self-RAG / Llama2 | Qwen1.5-14B-Chat (fine-tuned on OpenROAD) |
| Evaluator | T5 (`gsiresearch/t5-large-compact-v1`) | BGE-reranker-large (local, same function) |
| Task | PopQA, PubQA, etc. | OpenROAD EDA QA |

> **Note**: The original CRAG uses a T5 cross-encoder for retrieval assessment. Since HuggingFace is unreachable in our environment, we replaced it with the local fine-tuned BGE-reranker-large model, which serves the same purpose (scoring query-passage relevance).

### Why BGE Retrieval?

Same as Self-RAG baseline: using the benchmark's pre-retrieved `reranked_knowledge` would be **cheating**. We use independently retrieved BGE passages for fair evaluation.

### File Descriptions

#### Scripts (Input → Output)

| File | Input | Output | Description |
|------|-------|--------|-------------|
| `retrieve_with_bge.py` | `--corpus` (knowledge JSON), `--queries` (benchmark JSON), `--model` (BGE path), `--index_dir` (FAISS) | `--output` (`bge_retrieval_results.json`) | Loads corpus, builds/loads FAISS index, encodes queries with BGE, retrieves top-k passages |
| `convert_maeda_to_crag.py` | `--input` (benchmark JSON), `--retrieval_results` (BGE output) | `--output_dir` (`maeda_crag_data/`) | Converts MAEDA benchmark to CRAG format: queries.txt, retrieved.txt, eval_input.txt, gt.json |
| `crag_maeda_inference.py` | `--input_file` (benchmark), `--retrieval_results` (BGE), `--generator_path`, `--evaluator_path` | `--output_file` (`crag_raw_results.json`) | Scores retrieval with cross-encoder, refines knowledge, generates answers with Qwen |
| `postprocess_crag_output.py` | `--raw_results` (inference output), `--gt_data` (ground truth) | `--output` (`crag_maeda_eval_input.json`) | Cleans answers, structures for MAEDA evaluator |
| `run_eval.py` (external) | `eval_config_crag.json`, eval_input | `crag_maeda_eval_result.json` | MAEDA evaluator: LLM judges answer quality, detects error types |

#### Data Files

| File | Format | Description |
|------|--------|-------------|
| `maeda_crag_data/bge_retrieval_results.json` | `[{query_id, query, contexts: [{id, title, text, score}]}]` | BGE retrieval results per query |
| `maeda_crag_data/crag_queries.txt` | Plain text, one query per line | Questions extracted from benchmark |
| `maeda_crag_data/crag_retrieved.txt` | Plain text, passages joined by ` [sep] ` | Retrieved passages per query |
| `maeda_crag_data/crag_eval_input.txt` | Plain text, `query [SEP] passage` per line | Cross-encoder evaluator input |
| `maeda_crag_data/crag_gt.json` | `[{query_id, question, gt_answer, gt_answer_points, ...}]` | Ground truth for post-processing |
| `results/crag_raw_results.json` | `[{query_id, question, answer, knowledge, flag}]` | Raw inference output |
| `results/crag_maeda_eval_input.json` | `[{query_id, question, answer, input_answer, gt_answer, gt_answer_points, reranked_knowledge, error_type}]` | MAEDA evaluator input |
| **`results/crag_maeda_eval_result.json`** | `[{query_id, question, answer, detected_errors, error_detail, judge, ...}]` | **★ Final evaluation results** |

#### Final Result Format (`crag_maeda_eval_result.json`)

Each item contains:
- `query_id`: Question ID
- `question`: Original question
- `answer`: CRAG-generated answer
- `detected_errors`: List of error types detected, e.g. `["missing", "command_hallucination"]`
- `error_detail`: Per-error-type detail (e.g. which GT points are missing, which commands are hallucinated)
- `judge`: `true` (has errors) / `false` (no errors)

**Error types** (MAEDA 7-class):
- `missing`: GT answer points not covered in generated answer
- `command_hallucination`: Fabricated/non-existent commands
- `example_hallucination`: Fabricated code examples
- `retrieval_error`: Answer based on incorrect/irrelevant retrieved knowledge
- `contradiction`: Answer contradicts the ground truth

## Pipeline Steps

```
MAEDA Benchmark JSON
        │
        ▼
┌─────────────────────┐
│ Step 1: BGE Retrieval │  retrieve_with_bge.py
│   corpus → FAISS      │  → bge_retrieval_results.json
│   queries → top-k     │
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ Step 2: Convert      │  convert_maeda_to_crag.py

└──────────┬──────────┘
           ▼
┌─────────────────────────────────────┐
│ Step 3: CRAG Inference               │  crag_maeda_inference.py
│   ① BGE-reranker scores retrieval   │  → crag_raw_results.json
│   ② Classify: correct/ambiguous/incorrect │
│   ③ Refine knowledge by classification    │
│   ④ Qwen1.5-14B-Chat generates answer     │

           ▼
┌─────────────────────┐
│ Step 4: Post-process │  postprocess_crag_output.py

└──────────┬──────────┘
           ▼
┌─────────────────────┐
│ Step 5: MAEDA Eval   │  run_eval.py (external)
│   LLM judges quality │  → crag_maeda_eval_result.json ★
└─────────────────────┘
```

### BGE Retrieval Details

- Base model: `BAAI/bge-large-en-v1.5` (335M parameters, 1024-dim embeddings)
- FAISS index: 290 passages from OpenROAD knowledge corpus
- Query instruction prefix: `"Represent this sentence for searching relevant passages: "`
- Default top-k: 10

### BGE-reranker Evaluator

- Replaces original T5 evaluator (`gsiresearch/t5-large-compact-v1`) due to network restrictions
- Cross-encoder: scores each (query, passage) pair → relevance score
- Thresholds: `upper_threshold=0.5` (≥ → correct), `lower_threshold=-1.0` (≥ → ambiguous)
- Also used for knowledge refinement (selecting relevant strips from passages)

### Generator

- **Qwen1.5-14B-Chat** fine-tuned on OpenROAD domain data
- Uses chat template (`<|im_start|>system/user/assistant`) for prompt formatting
- Runs with vLLM (dtype=half, gpu_memory_utilization=0.90)
- Default: temperature=0.0, max_tokens=512

## Usage

### Run full pipeline

```bash
CUDA_VISIBLE_DEVICES=4 bash run_crag_maeda.sh
```

The script auto-activates the uv venv. Steps 1-4 run locally; Step 5 calls external LLM API.

### Run individual steps

```bash
bash run_crag_maeda.sh retrieve     # Step 1: BGE retrieval only
bash run_crag_maeda.sh convert      # Step 2: Data conversion only
bash run_crag_maeda.sh inference    # Step 3: CRAG inference only (needs GPU)
bash run_crag_maeda.sh postprocess  # Step 4: Post-processing only
bash run_crag_maeda.sh eval         # Step 5: MAEDA evaluation only
```

### Use a different GPU

```bash
CUDA_VISIBLE_DEVICES=5 bash run_crag_maeda.sh
```

### Run with nohup (recommended for long runs)

```bash
nohup bash -c 'CUDA_VISIBLE_DEVICES=4 bash run_crag_maeda.sh' > /tmp/crag_run.log 2>&1 &
# Monitor: tail -f /tmp/crag_run.log
```

### Run with simple RAG (skip evaluator, no corrective mechanism)

```bash
# Edit METHOD in run_crag_maeda.sh:
sed -i 's/METHOD="crag"/METHOD="rag"/' run_crag_maeda.sh
CUDA_VISIBLE_DEVICES=4 bash run_crag_maeda.sh inference
```

### Override evaluator path

```bash
EVALUATOR_PATH=/path/to/other/reranker CUDA_VISIBLE_DEVICES=4 bash run_crag_maeda.sh inference
```

## Key Configuration

### `run_crag_maeda.sh` variables

| Variable | Default | Description |
|----------|---------|-------------|
| `MODEL_PATH` | Qwen1.5-14B-Chat merged | Generator model path |
| `EVALUATOR_PATH` | BGE-reranker-large | Cross-encoder evaluator path |
| `BGE_MODEL_PATH` | BGE-large-en-v1.5 | Embedding model path |
| `CORPUS_PATH` | `knowledge_openroad_MAEDA.json` | Knowledge corpus |
| `FAISS_INDEX_DIR` | `faiss_bge_selfrag/` | FAISS index directory |
| `NDOCS` | 10 | Number of docs per question |
| `RETRIEVAL_TOPK` | 10 | BGE retrieval top-k |
| `MAX_NEW_TOKENS` | 512 | Max generation tokens |
| `METHOD` | `crag` | `crag` (corrective) / `rag` (vanilla) / `no_retrieval` |
| `UPPER_THRESHOLD` | 0.5 | Reranker score ≥ this → correct |
| `LOWER_THRESHOLD` | -1.0 | Reranker score ≥ this → ambiguous |
| `DECOMPOSE_MODE` | `selection` | Knowledge decomposition strategy |

### `eval_config_crag.json`

Controls MAEDA evaluator: LLM API (`model`, `base_url`, `api_key`), input/output paths, and evaluation options (`eval_keypoints`, `eval_hallucination`).

## CRAG vs Self-RAG Baseline

| Feature | Self-RAG | CRAG |
|---------|----------|------|
| Retrieval evaluation | Self-reflection tokens | Cross-encoder evaluator (BGE-reranker) |
| Knowledge refinement | Adaptive retrieval during generation | Pre-generation knowledge assessment |
| Generator | selfrag_llama2_7b | Qwen1.5-14B-Chat (fine-tuned) |
| Model size | 7B | 14B |
| Retrieval timing | During generation (adaptive) | Before generation (corrective) |
| Evaluator | Built-in (reflection tokens) | External (BGE-reranker cross-encoder) |
